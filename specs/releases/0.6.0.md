## pageslens 0.6.0

Page access rules for classic sites: eight lint rules and a `pages.md` docs page that says who can read each page.

### New

- **Page access rules in `lint`** (classic sites). Eight rules check the rules that decide who can open a page:
  - `page-rule-no-page`: a rule with no page, or a missing or inactive one (info for the template's "Grant Change to Content", which has neither a page nor a role);
  - `page-rule-no-role`: a Restrict Read with no role hides its branch (error); a Grant Change with no role does nothing (info);
  - `page-rule-anonymous` (error): a rule lists the Anonymous Users role, which lets nobody in, anonymous visitors included;
  - `page-rules-conflict`: more than one Restrict Read on a page;
  - `page-roles-not-subset`: a Restrict Read lists a role that a Restrict Read above keeps out;
  - `grant-change-overrides-read`: a Grant Change role reads past a Restrict Read ("Restrict read doesn't work for admins");
  - `page-rule-authenticated`: a Restrict Read lists Authenticated Users with other roles, so every signed-in user gets in;
  - `page-parent-missing`: a page whose parent is missing or inactive, or whose parents loop.
- **`pages.md` in `docs`** (classic sites): every page by URL, who can read it and which rules decide that, the Grant Change roles, every rule with its scope, and the inactive pages and rules. How rules combine was checked on a real classic site: Restrict Read rules down the tree narrow access, and Grant Change overrides them whatever its scope.
- A rule can report findings at different severities (`page-rule-no-page`, `page-rule-no-role`, `page-parent-missing`). Setting the rule's severity in `pageslens.config.yaml` still sets it for every finding.

Code sites are unchanged: page access rules don't decide who sees a page there, so none of this runs on them.

### Fixed

- **Inactive records are left out.** Downloads include records that are inactive in Dataverse (`statecode: 1`), and pageslens read them as active. An inactive table permission set off `global-write-anonymous` and other rules, and showed up in the access matrix, in `test` and in `diff`. Now inactive table permissions, web roles, site settings, page access rules and website access records take part in nothing, as in Power Pages. `docs` says how many were left out. In `diff`, deactivating a record reads as removing it (`(deactivated)`), and activating one as adding it (`(activated)`). `permission-no-role` and `parent-chain-broken` say when the role or parent they point at is inactive.
- **GitHub Action:** the access-changes comment now compares the pull request's own head commit with the merge base, as GitHub's diff does. Before, it named the merge commit that `actions/checkout` creates for a pull request, which isn't one of the pull request's commits. The changes it found were the same.
- **`pageslens diff`:** a ref that is a commit id is shown once, short (`a1b2c3d`), instead of in full followed by the short id.

### Upgrading

Update the action to `OOlashyn/pageslens@v0.6.0`.

```bash
npm install --save-dev pageslens@0.6.0
```
