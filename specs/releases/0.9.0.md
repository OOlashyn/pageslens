## pageslens 0.9.0

`pageslens align`: for teams that commit both a site download and the solution that deploys it, a check that the two describe the same site, so a component left out of the solution shows in the pull request instead of after the import. Also a lint rule for secrets typed into site settings.

### New

- **`pageslens align <site> <solution>`.** New site components aren't added to a solution automatically, so a web role, a table permission or a page made in dev works there, is in the download, and is missing in test and prod. `align` compares the download with the unpacked solution, record by record, matched by GUID:

  ```bash
  npx pageslens align site solution
  ```

  ```
  align site (classic site download) with solution/src (PagesLensEDM2Sol 1.0.0.0)

  ✗ missing from the solution: won't be in test or prod
      web role "Course Admins"  webrole.yml
  ✗ content differs
      site setting "Search/Enabled": value is "true" in the download, "false" in the solution
        sitesetting.yml
        powerpagecomponents/9c1e0a2b-7d4e-4f31-8a6c-2b5d9e0f1a77/powerpagecomponent.xml

  2 errors, 0 warnings. 475 records match.
  ```

  It reports records in the download that the solution doesn't have (a warning when the record is inactive), components in the solution that the download doesn't have, records active on one side only, fields, text and web file content that differ, fields only one side writes, and environment variables the import needs: one missing from the solution, or one with no value. What two snapshots of one site always differ in isn't reported: the keys a classic download prefixes, empty side files, JSON formatting, role order, and a few fields only one side writes. On the two sites it was checked on, a download and its solution give no findings. Tables aren't checked, since they usually live in a solution of their own.

  The exit code is `0` without errors, `1` with errors, and `2` when a side is the wrong kind or can't be read. Output is text, `--format json`, `markdown` (for a pull request comment) or `sarif`. See [docs/align.md](https://github.com/OOlashyn/pageslens/blob/main/docs/align.md).

- **An `align` section in `pageslens.config.yaml`**: a severity per check, and ignores by record GUID for components kept out of the solution on purpose. Unused ignores are listed, as for `lint`. The config schema has the section, for completion in editors.

  ```yaml
  align:
    checks:
      missing-from-download: off
    ignore:
      - records: [3453215b-d450-4073-a12c-88aa8a248b81]
        reason: Test page, kept out of the solution on purpose
  ```

- **The GitHub Action's `solution` input** runs `align <path> <solution>` too. The results are uploaded to code scanning with lint and test, the findings go into the pull request comment above the access changes, and errors fail the job. A new output, `align-errors`, gives their count. It's off by default: set it when you commit both a download and the solution taken from dev together.

  ```yaml
  - uses: OOlashyn/pageslens@v0.9.0
    with:
      path: site
      solution: solution
  ```

- **`setting-secret-value`** (error). A site setting whose name ends in `ClientSecret`, `AppSecret` or `ConsumerSecret` with a value of its own puts an identity provider's secret in every download and solution of the site, and so in git. Rotate the secret, keep it in an environment variable of type Secret (Azure Key Vault), and clear the setting. Empty settings and settings backed by an environment variable don't fire. See [rules/setting-secret-value.md](https://github.com/OOlashyn/pageslens/blob/main/rules/setting-secret-value.md).

### Upgrading

`setting-secret-value` is an error, so `lint` exits `1` (and the action fails) on a site with a secret typed into a setting, where it passed before, and it adds a code scanning alert if you upload SARIF. Rotate the secret: it's already in git. To keep a placeholder on a development site, ignore its record in that site's `pageslens.config.yaml`.

Nothing else changes unless you use `align`. Without the `solution` input the action runs as before. The JSON outputs' `version` is still 1.

```bash
npm install --save-dev pageslens@0.9.0
```

Update the action to `OOlashyn/pageslens@v0.9.0`.
