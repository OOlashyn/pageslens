## pageslens 0.3.0

Policies: write your site's access requirements as short sentences and check them on every pull request with `pageslens test`.

### New: `pageslens test`

```bash
npx pageslens test path/to/site
```

`lint` catches known mistakes. `test` checks **your** requirements, from a `pageslens.policy.yaml` in the site folder or any folder above it (or `--policy <file>`):

```yaml
access:
  - anonymous cannot create, write, delete any table
  - role "Case Manager" can read, write incident at contact scope
  - only "Case Manager", "Administrators" can write incident
  - nobody can delete account
  - id: invoices-billing-only
    check: only "Billing" can read, write dwcrm_invoice
    because: Invoices are financial records
webapi:
  - fields are explicit
  - only contact, incident are enabled
  - anonymous cannot call any table
settings:
  - registration is invite only
  - setting "Webapi/error/innererror" is "false"
```

- **One sentence per requirement, from a fixed set of forms.** Access statements (`can`, `cannot`, `only … can`, `nobody can`, with an optional scope and `any table`), Web API statements, and site setting statements. A sentence that doesn't match a form is an error that gives its line and what was expected.
- **`authenticated` means every signed-in user.** Power Pages gives every signed-in user the Authenticated Users role. So `authenticated cannot …` fails if any role except Anonymous Users has the access, and `role "Case Manager"` also counts what Authenticated Users can do.
- **`only` lists catch new access.** `only "Billing" can read dwcrm_invoice` fails when someone adds another role with access next month, which a `cannot` list would miss.
- **Failures point at the cause.** Each failed statement lists the grants or settings that break it, with their files. Role names are checked against the site, with a suggestion for a close match ("did you mean `Case Manager`?"). A table the site never mentions gets a warning.
- **`registration is invite only`** follows Microsoft's defaults, where open registration is on unless turned off. A site without those settings fails, and the output explains why.
- **`--format json`** gives a versioned object for scripts and agents.

Exit codes: `0` every statement passes, `1` at least one fails, `2` no policy file, an empty policy, a statement pageslens can't read, or an unknown role.

The grammar, what each statement means, and tips for writing a policy are in [docs/policy.md](https://github.com/OOlashyn/pageslens/blob/main/docs/policy.md). (#12)

### Upgrading

Nothing changes for `lint` or `docs`. If you add `pageslens test` to CI, add a `pageslens.policy.yaml` in the same change: without one, `test` exits `2` on purpose, so a step that checks nothing can't pass.

A statement that starts with a role name needs `role` in front (`role "Case Manager" can …`), because YAML can't read a list item that starts with a quoted name and continues after it.

```bash
npm install --save-dev pageslens@0.3.0
```
