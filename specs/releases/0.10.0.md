## pageslens 0.10.0

Help for agents and people reading findings: `pageslens explain` prints why a lint rule matters and how to fix it, offline, for the version you run, and the README has a section on using pageslens from a coding agent. Also `diff --site`, for the site folder when comparing two refs.

### New

- **`pageslens explain [rule]`.** `explain <rule>` prints the rule's page: what it catches, why it matters and how to fix it. `explain` alone lists the rules with their default severity:

  ```bash
  npx pageslens explain scope-relationship-missing
  npx pageslens explain
  ```

  ```
  global-write-anonymous        warning  Global scope create, write or delete for the Anonymous Users role.
  global-write-authenticated    warning  Global scope create, write or delete for the Authenticated Users role.
  grant-change-overrides-read   warning  A Grant Change rule lets a web role read pages that a Restrict Read on or below its page doesn't list.
  ...
  ```

  The rule pages now ship in the npm package, so `explain` works offline and through `npx`, and shows the page of the version that gave the finding. An unknown rule exits `2` and suggests the closest one. The pages are still linked from each finding's `docs` in JSON and SARIF.

- **A pointer to `explain` in `lint`'s text output.** When there are findings, the output ends with one more line:

  ```
  4 errors, 1 warning, 0 info
  Run pageslens explain <rule> for why it matters and how to fix it.
  ```

- **[Using pageslens with an agent](https://github.com/OOlashyn/pageslens#using-pageslens-with-an-agent)**, a README section to point a coding agent at, or to paste into your `AGENTS.md` or `CLAUDE.md`: how to run pageslens, the working rules (pageslens decides what's a finding or a wider change; work offline; find records by GUID; don't guess a value that comes from an environment variable; run `lint` again after every fix), and three short recipes: review a site, review a pull request's access changes, and write narrative docs next to the ones `docs` generates.

- **`diff --site <path>`.** With two refs, the site folder now goes in `--site`, so the positionals are only the two sides:

  ```bash
  npx pageslens diff origin/main HEAD --site site --merge-base
  ```

### Deprecated

- **The site folder as `diff`'s third argument** (`diff origin/main HEAD site`). It still works, with a warning on stderr, and will be removed in a later release. Giving both it and `--site` is an error. The GitHub Action already passes `--site`.

### Upgrading

Nothing fails that passed before. Two things change in output:

- `lint`'s text output has a new last line when there are findings. A script that reads the summary from the last line should read `--format json` instead, which hasn't changed.
- `diff` with a third argument writes a warning to stderr. Move the folder to `--site`.

The JSON outputs' `version` is still 1, and SARIF hasn't changed.

```bash
npm install --save-dev pageslens@0.10.0
```

Update the action to `OOlashyn/pageslens@v0.10.0`. Its inputs haven't changed.
