## pageslens 0.7.0

Page access in `test` and `diff`, for classic sites: a policy can say who may open a page, and a pull request shows who gained or lost access to pages.

### New

- **Page statements in `test`.** A new `pages` section in `pageslens.policy.yaml`:

  ```yaml
  pages:
    - anonymous cannot read page "/my-registrations/"
    - only "C1 ASP" can read pages under "/admin/"
    - only "Administrators" can publish pages under "/"
  ```

  `page "<url>"` is one page and `pages under "<url>"` a page and every page below it, so a page added later is checked too. URLs match without case, as in Power Pages. `publish` is about Grant Change rules. A failure names the rule that lets someone in or keeps them out, or the page when no rule restricts it. A URL with no page, or an inactive one, is an error. See [docs/policy.md](https://github.com/OOlashyn/pageslens/blob/main/docs/policy.md#page-statements).

- **Pages in `diff`.** When both sides are classic sites, `diff` compares who can read and publish each page: "Anyone can now read /internal/ (and 4 pages below it): Restrict Read rule "Employees Only" removed". New pages anyone can read are wider; removed pages narrower; moved pages and the same access from other rules neutral. A change shared by a branch is one line on its topmost page; the JSON output lists every page. See [docs/diff.md](https://github.com/OOlashyn/pageslens/blob/main/docs/diff.md#pages).

Code sites are unchanged: page statements are an error there, and `diff` compares no pages.

### Upgrading

`diff --fail-on wider` may now fail on a pull request that adds a public page or opens one up. The JSON output has new change kinds (`page-…`) and two new fields (`page`, `pages`); its `version` is still 1.

```bash
npm install --save-dev pageslens@0.7.0
```

Update the action to `OOlashyn/pageslens@v0.7.0`.
