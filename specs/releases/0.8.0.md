## pageslens 0.8.0

A lint rule for Web API inner errors, and `lint` now lists ignore entries that no longer match anything.

### New

- **`webapi-inner-errors`** (warning). `Webapi/error/innererror = true` makes a failed Web API call return the server error behind it. That helps in development, and Microsoft's Web API walkthrough turns it on, but on a live site it tells anyone who calls the API more than they need. Set it to `false` or remove it outside development. See [rules/webapi-inner-errors.md](https://github.com/OOlashyn/pageslens/blob/main/rules/webapi-inner-errors.md).
- **Unused ignore entries.** `lint` lists each `files` glob or `records` GUID in a `pageslens.config.yaml` ignore entry that left out no finding, under the config file's name, so an entry for something since fixed doesn't hide the next finding there:

  ```
  pageslens.config.yaml
    warning  Ignore entry 2: file "web-roles/Legacy-*.webrole.yml" matches no finding; remove it if what it ignored is fixed.

  4 errors, 0 warnings, 0 info, 1 ignored, 1 unused ignore
  ```

  They don't fail the run and aren't in SARIF. An entry that lists a rule that's turned off isn't checked. In JSON they're the new `unusedIgnores` field (`entry`, counted from 1, `field` and `value`).

### Upgrading

Sites with `Webapi/error/innererror = true` get one more warning, and a new code scanning alert if you upload SARIF. Warnings don't change the exit code. To keep the setting on a development site, ignore its record in that site's `pageslens.config.yaml`, or set the rule to `off`.

The JSON output's `version` is still 1: `unusedIgnores` is an added field.

```bash
npm install --save-dev pageslens@0.8.0
```

Update the action to `OOlashyn/pageslens@v0.8.0`.
