## pageslens 0.5.0

pageslens now comes as a GitHub Action: one step runs `lint` and `test`, uploads the results to code scanning, and posts what a pull request does to access as a comment.

### New: the pageslens GitHub Action

```yaml
- uses: actions/checkout@v4
  with:
    fetch-depth: 0
- uses: OOlashyn/pageslens@v0.5.0
  with:
    path: site
```

- **One comment per site, edited in place.** On a pull request the action runs `pageslens diff --merge-base` against the base branch and posts the result as a comment, which later runs edit. With no access changes it doesn't add a comment; it edits an earlier one to say so. The same text goes to the run's summary page.
- **Code scanning alerts.** Lint findings and failed policy statements are uploaded as SARIF, so they show up on the pull request and in the **Security** tab. Run the action on pushes to `main` too, so code scanning can tell which alerts a pull request adds.
- **Every step runs, then the job fails** if lint found errors, a policy statement failed, or `fail-on: wider` matched. A failing lint doesn't hide the diff.
- **Safe defaults.** It runs exactly pageslens 0.5.0 from npm, with no install scripts. Pull requests from forks get a read-only token, so there the results go to the summary page only. A missing permission is a notice, not a failure.
- **No policy yet?** `test` is skipped with a notice, so you can start with `lint` and `diff`.

The README's [GitHub Action](https://github.com/OOlashyn/pageslens#github-action) section lists the inputs, outputs and permissions.

### Fixed

- **`pageslens diff --format markdown`:** an `@` in a role or permission name no longer mentions a GitHub user or team in the comment.

### Upgrading

Nothing changes for existing `lint`, `test`, `diff` or `docs` runs. If you copied the README's workflows, you can replace them with the action; they still work.

```bash
npm install --save-dev pageslens@0.5.0
```
