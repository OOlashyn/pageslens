## pageslens 0.4.0

See what a pull request does to your site's access with `pageslens diff`, and get `lint` and `test` results as GitHub code scanning alerts with `--format sarif`.

### New: `pageslens diff`

```bash
npx pageslens diff origin/main HEAD path/to/site
```

The YAML diff shows which files changed. `pageslens diff` shows what the change means: **who gained or lost access to what**.

```
Access changes in site/.powerpages-site, origin/main (a1b2c3d) → HEAD (e4f5a6b): 2 wider, 1 narrower, 1 neutral

Wider
  + Authenticated Users gained read, write on contact (global scope) from "Contact - Authenticated Users Global Write" (Web API enabled) (also reported by lint: global-write-authenticated)
  + Customers: write on incident changed from contact scope to global scope in "Incident - Customers"
Narrower
  - Anonymous Users lost read on knowledgearticle (global scope) from "Articles - Anonymous Read" (removed)
Neutral
  ~ Role "Customer" renamed to "Customers"
```

- **Compares effective access, not files.** It covers:
  - grants per role, table and scope, including child permissions that take their parent's roles;
  - the Web API: tables enabled, fields exposed, who can call it;
  - web roles: added, removed, renamed, recreated, or becoming the Anonymous or Authenticated Users role;
  - five security-relevant settings: registration, invitations, Web API inner errors and CORS.

  Records are matched by GUID, so renamed or moved files, a permission split in two, or a different download layout aren't reported as access changes.

- **Every change is wider, narrower or neutral.** Wider means someone may now reach something they couldn't, and the rules are cautious: a change pageslens can't show to be narrower counts as wider. Changes are listed most exposed first, starting with anonymous visitors.
- **Folders or git refs.** Compare two downloads, two commits, or a commit with your working tree (`pageslens diff origin/main site`). Commits are read straight from git, without a checkout. `--merge-base` compares with the merge base, as a pull request does.
- **Made for pull requests.** `--format markdown` writes a comment: counts first, details folded, a hidden marker so a workflow can update its own comment, and a cap under GitHub's 65,536-character limit. `--format json` gives a versioned object with everything.
- **Informational by default.** It exits `0` whatever changed. Add `--fail-on wider` (or `--fail-on any`) to fail the build on widened access, for example unless a label approves it.

Page access rules, Server Logic, cloud flows and website access aren't compared yet. The full reference, with every kind of change and how it's classified, is in [docs/diff.md](https://github.com/OOlashyn/pageslens/blob/main/docs/diff.md). (#15)

### New: `--format sarif` for `lint` and `test`

```bash
npx pageslens lint site --format sarif > lint.sarif
npx pageslens test site --format sarif > test.sarif
```

Upload the files with GitHub's `upload-sarif` action. Lint findings and failed policy statements then appear as annotations on the pull request and in the repository's **Security** tab.

- **Alerts land on the right line.** A result points at the line of the record's GUID, even in classic list files like `webrole.yml` where every role shares one file. A failed policy statement is reported on each table permission or setting that breaks it, with the statement's line in the policy file attached.
- **Severities carry over.** Errors, warnings and info become errors, warnings and notes, with GitHub security severity high, medium and low.
- **Lint and test stay separate.** Each run has its own category, so you can upload both. Give policy statements an `id` if you want their alerts to keep their identity when you reword them.
- **Exit codes don't change** with `--format sarif`.

The README's [In CI](https://github.com/OOlashyn/pageslens#in-ci) section has a complete workflow that writes both files and uploads them. (#14)

### Changed

- **`pageslens test --format json`:** evidence for a failed `can` statement now marks what the role _does_ have as `"context": true`, so tools can tell causes from background. Nothing else in the JSON changed, and the format version stays `1`.

### Upgrading

Nothing changes for existing `lint`, `test` or `docs` runs.

To use `diff` with `--merge-base` in CI, check out the full history (`actions/checkout` with `fetch-depth: 0`); the merge base needs both branches. The README shows a workflow that writes the diff to the job summary. A GitHub Action that posts it as a pull request comment is planned.

```bash
npm install --save-dev pageslens@0.4.0
```
